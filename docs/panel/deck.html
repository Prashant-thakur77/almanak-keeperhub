The problem

Almanak has a clean execution layer that only knows one way to execute

  • Almanak is an open-source DeFi strategy framework (PyPI almanak, 46 protocol connectors). Its execution layer is three abstract classes: Signer, Simulator, Submitter.
  • The only submitter that ships is the public mempool; the private relay is a stub that rejects every transaction.
  • The private key lives on the strategy machine. No idempotency: their own repo carries a duplicate-mint incident after a nonce error (nonce_recovery.py).
  • The gateway's wallet-registry plugin can name a wallet, but cannot say how it signs: an unknown wallet kind is refused, and the submitter and simulator are always the built-in ones.
  • So an agent that runs an Almanak strategy has custody, retries and guards to solve by itself, exactly what KeeperHub already does.

Filed upstream with a diff that applies to their main: almanak-co/sdk#3, a pluggable almanak.execution_backends entry-point group. Two Almanak bugs found on the way (a 30 s gateway deadlock with a wallet plugin installed; simulate never enabled on live networks), both since fixed on their main.

How it is proven

The guard runs next to the write, and a machine repeats the proof every six hours

The guarded exit, two ways. An exit decision can be stale by the time it executes. /exit sends the redeem as KeeperHub check-and-execute: KeeperHub reads balanceOf(wallet) right before the write. /guard triggers the workflow on the right: KeeperHub's own engine reads the shares, the Condition compares, the redeem sits behind the true branch.

Next

  • Mainnet. The code path is identical; only funding was withheld. doctor and the console footer already say which chain is live.
  • Whole strategies as KeeperHub workflows. The exit guard is the first node graph the package generates from a strategy; the compounder is the second. With #2531's preflight, every later node is dry-run against the state the earlier ones produce before anything is enabled.
  • Almanak's Safe plus Zodiac Roles mode mapped onto KeeperHub's policy layer: roles decide what an agent may call, KeeperHub decides whether it lands.
  • Agents as operators. The MCP server already serves the strategy with KeeperHub's read/write key split; next, the guard becomes the default shape of every agent write.
  • The Almanak side. When almanak.execution_backends lands, the package needs no subclass at all: a registry entry of kind keeperhub is the whole integration.
